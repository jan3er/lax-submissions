## 1. Supervisor correction to the plan's source table (F12)

The rev 5 plan text records, for `Hnr_Primitives_Experiment.thy`:

> Carries **one `sorry`**, at `FREE_eoarray_assn:318–325` (the `MK_FREE`
> deallocation frame rule)

**That is wrong in a way that matters.** The declaration at `:318–325` is
*inside a comment block* opened at `:316` and closed at `:326`. The file
carries **no live `sorry`**; `grep -c sorry` returns 1 and that one
occurrence is commented out. The comment's own text is:

```
(* This rule does not hold! The elements must be de-allocated first!
  for explicit ownership management, free the array manually using mop_oarray_free!
lemma FREE_eoarray_assn[sepref_frame_free_rules]:
  shows "MK_FREE (eoarray_assn A) narray_free"
  ...
  sorry
*)
```

The correction *strengthens* the exclusion of the deallocation frame rule
and simultaneously *narrows* it:

- **Stronger.** The artifact does not merely leave `MK_FREE (eoarray_assn A)`
  unproved; it states that the rule **does not hold**. An automatic
  frame-level free for an explicit-ownership array is unsound, because the
  frame rule would drop element ownership that the array does not own. We are
  not deferring a proof obligation the source left open — we are declining to
  state a false theorem. That is not a deviation at all.
- **Narrower.** Deallocation *itself* is supported by the source and proved:
  `mop_oarray_free` (`:328`) with `hnr_eoarray_free` (`:330–340`) discharges
  under the precondition `set xs ⊆ {None}` — every element moved out first.
  So "deallocation is excluded" is **our** decision about the substrate, not a
  gap in the source, and it must be argued on our own terms rather than by
  pointing at a `sorry` that is not there.

Consequences, both scheduled:

- Ledger E23 restates the deallocation exclusion on the correct basis (peak
  memory equals total allocation, because a non-reusing bump allocator is
  what buys the O(1) result — free and O(1) alloc are the same trade, taken
  once).
- Exclusion **X17**'s clause (c) cites "the source's own evidence that its
  `MK_FREE` rule is the artifact's single `sorry`". That citation is void.
  X17(c) survives on E23's reasoning instead; the row is amended, not
  reopened, because clauses (a) and (b) are independently sufficient.

## 2. What the source's allocator actually costs, and why ours is cheaper

The plan says our O(1) is "stronger than the source's `cost'_narray_new n`
[because] the machine starts zeroed … no fill loop". The conclusion is right
and the reason as stated is not, so it is recorded here precisely — a worker
reading only the plan would look for a fill loop in the source and not find
one.

**The source has no fill loop either.** The chain is:

```isabelle
(* Proto_EOArray.thy:147 *)
definition "narrayo_new TYPE('a::llvm_rep) n \<equiv> narray_new TYPE('a) n"

(* LLVM_DS_NArray.thy:14-15 *)
definition [llvm_inline]:
  "narray_new TYPE('a::llvm_rep) n \<equiv>
     doM { b \<leftarrow> ll_icmp_eq n (signed_nat 0); llc_if b (return null) (array_new TYPE('a) n) }"
```

`narray_new` is a null-check plus a raw `array_new`; the contents are never
written. The array is legitimately handed back holding garbage because of:

```isabelle
(* Proto_EOArray.thy:114 *)
lemma lo_init: "\<upharpoonleft>(list_assn (oelem_assn A)) (replicate n None) (replicate n x) = \<box>"
```

An all-`None` EO array **owns no element memory whatsoever**, for *any*
concrete contents `x`. That is the load-bearing fact of the whole substrate,
and it is what makes a contents-blind allocator sound.

So the source's `n` is not initialisation:

```isabelle
(* Hnr_Primitives_Experiment.thy:202 *)
abbreviation "cost'_narray_new n \<equiv>
  cost ''malloc'' n + cost ''free'' 1 + cost ''if'' 1 + cost ''if'' 1
  + cost ''icmp_eq'' 1 + cost ''ptrcmp_eq'' 1"
```

The `n` is charged to the `malloc` **currency**: LLVM's allocator is modelled
as costing proportionally to the block it hands out, which for a real `malloc`
is the honest assumption. The five trailing constants are the null-check, the
`llc_if`, and the deferred `free`/`ptrcmp` pair that `narray_assn` carries
(`LLVM_DS_NArray.thy:10`) so that deallocation is prepaid at allocation time.

**Our substrate does not have that cost.** `Lax13/Ram.lean` gives `2^w` cells
that already exist and already hold zero; a bump allocator reads a pointer
cell, adds `n`, writes it back, and returns the old value — a fixed number of
IR steps independent of `n`. The deviation is therefore *substrate*, not
*optimisation*: we are not doing the source's work faster, we are on a machine
where that work does not exist. Ledger E24 states it that way, because "we
made malloc O(1)" would be a false claim about an LLVM program.

Two obligations follow, and neither may be assumed:

- **No-reuse is what buys it.** Fresh cells are zero only because the
  allocator never returns a cell twice. The invariant is stated and enforced,
  not commented. If free/reuse is ever added the O(1) bound reverts and every
  consumer's cost claim reverts with it.
- **Exhaustion is global.** Total allocation ≤ `2^w`, stated once at program
  level, mirroring the source's standing "given `malloc` succeeds". Rule 5
  forbids pushing it down onto individual operations — that push is exactly
  what produced the conditional `append` this phase exists to remove.

## 3. The declarations P4.5 ports, verbatim

### A — allocation (`Hnr_Primitives_Experiment.thy`)

```isabelle
(* :183, the generic no-cost shape, parameterised by a cost function T *)
definition [simp]: "mop_olist_new n \<equiv>
  do { ASSERT (PROTECT True); consume (RETURNT (replicate n None)) (T n) }"

(* :229-231, the costed instance and its unfolding *)
definition "mop_oarray_new \<equiv> mop_olist_new (\<lambda>n. lift_acost (cost'_narray_new n))"
lemma "mop_oarray_new n = consume (RETURNT (replicate n None)) (lift_acost (cost'_narray_new n))"

(* :285-291, the hn_refine rule *)
lemma hnr_eoarray_new: "hn_refine
  (hn_ctxt snat_assn i ii)
  (narrayo_new TYPE('a::llvm_rep) ii)
  (hn_ctxt snat_assn i ii)
  (eoarray_assn A)
  (mop_oarray_new i)"

(* :295-297, the registered signature form *)
lemma hnr_eoarray_new'[sepref_fr_rules]: "( (narrayo_new TYPE('a::llvm_rep)), mop_oarray_new )
       \<in> snat_assn\<^sup>k \<rightarrow>\<^sub>a (eoarray_assn A)"
```

Note the shape of the `hn_refine` rule: the size argument `i` is **kept**
(`hn_ctxt` on both sides, `snat_assn\<^sup>k`), and allocation has **no
precondition** — no `ASSERT` beyond `PROTECT True`, which is a tagging
no-op. That unconditionality is the property P4.5 exists to reproduce, and
it is the acceptance test named in the plan: `arrayListReadyRel` and
`daReadyRel` are deleted and both pushes are restated with no
caller-supplied backing store.

### B — element ownership (`Hnr_Primitives_Experiment.thy`, `Proto_EOArray.thy`)

```isabelle
(* :199-200, the per-operation costs *)
abbreviation "mop_array_nth_cost \<equiv> (cost ''load'' (Suc 0) + cost ''ofs_ptr'' (Suc 0))"
abbreviation "mop_array_upd_cost \<equiv> (cost ''store'' (Suc 0) + cost ''ofs_ptr'' (Suc 0))"

(* :221-226 *)
definition "mop_oarray_extract \<equiv> mop_eo_extract (\<lambda>_. lift_acost mop_array_nth_cost)"
lemma "mop_oarray_extract xs i =
  doN { ASSERT (i<length xs \<and> xs!i\<noteq>None);
        consume (RETURNT (the (xs!i), xs[i:=None])) (lift_acost mop_array_nth_cost) }"
definition "mop_oarray_upd \<equiv> mop_eo_set (\<lambda>_. lift_acost mop_array_upd_cost)"
lemma "mop_oarray_upd xs i x =
  do { ASSERT (i<length xs \<and> xs!i=None);
       consume (RETURNT (xs[i:=Some x])) (lift_acost mop_array_upd_cost) }"

(* Proto_EOArray.thy:79, the ownership element *)
definition "oelem_assn A \<equiv> mk_assn (\<lambda>None \<Rightarrow> \<lambda>_. \<box> | Some x \<Rightarrow> \<lambda>xi. \<upharpoonleft>A x xi)"

(* Proto_EOArray.thy:144, the array *)
definition "nao_assn A \<equiv> mk_assn (\<lambda>xs p. EXS xsi. \<upharpoonleft>narray_assn xsi p ** \<upharpoonleft>(list_assn (oelem_assn A)) xs xsi)"

(* Hnr_Primitives_Experiment.thy:234 *)
definition "eoarray_assn A \<equiv> \<upharpoonleft>(nao_assn (mk_assn A))"

(* Proto_EOArray.thy:114,117,128-142 — the four structural laws *)
lemma lo_init: "\<upharpoonleft>(list_assn (oelem_assn A)) (replicate n None) (replicate n x) = \<box>"
lemma lo_free: "set xs \<subseteq> {None} \<Longrightarrow>
  \<upharpoonleft>(list_assn (oelem_assn A)) xs xsi = \<up>(length xsi = length xs)"
lemma lo_extract_elem: "i<length xs \<Longrightarrow> xs!i = Some x \<Longrightarrow>
  \<upharpoonleft>(list_assn (oelem_assn A)) xs ys = ((\<upharpoonleft>A x (ys!i)) ** \<upharpoonleft>(list_assn (oelem_assn A)) (xs[i:=None]) ys)"
lemma lo_insert_elem: "i<length xs \<Longrightarrow> xs!i = None \<Longrightarrow>
  \<upharpoonleft>(list_assn (oelem_assn A)) (xs[i:=Some x]) (ys[i:=y]) = (\<upharpoonleft>A x y ** \<upharpoonleft>(list_assn (oelem_assn A)) xs ys)"
```

`lo_extract_elem` and `lo_insert_elem` are exact **equations**, not
entailments, and `extract`/`upd` are exact inverses on the ownership tag.
That is the mechanism behind the source's `myswap` and the reason move costs
come out exact rather than bounded.

### Deallocation — supported by the source, excluded by us

```isabelle
(* :328 *)
definition "mop_oarray_free xs \<equiv> do { ASSERT (set xs \<subseteq> {None}); consume (RETURNT ()) (lift_acost 0) }"
(* :330-340, proved *)
lemma hnr_eoarray_free[sepref_fr_rules]: "hn_refine
  (hn_ctxt (eoarray_assn A) xs xsi) (narray_free xsi)
  (hn_invalid (eoarray_assn A) xs xsi) (id_assn) (mop_oarray_free $ xs)"
```

Free costs `0` here precisely because `narray_assn` prepaid it at allocation
(the `cost ''free'' 1 + cost ''ptrcmp_eq'' 1` in `cost'_narray_new`). See §1
for why the *frame* rule above it is excluded and §2 for why we exclude
deallocation outright.
